## 1. TD-08 — 프롬프트 출력 순서 체계 (ADR-062)

**문제**: 속성의 `order` 하나가 UI 순서와 출력 순서를 함께 맡고 있었습니다. 새 영역을 넣을 때마다 번호를 다시 매겨야 했습니다(×10 번호 공간, 비인물 +1000 오프셋).

**해결**: 카탈로그 형식 0.5.0에 선택 필드 `promptOrder`를 추가했습니다. 가장 작은 변경으로 해결하는 방식을 택했습니다.

```text
promptOrder: [
  { id: "subject",         attributes: ["intent.description", "subject.kind", "person.appearance.direction"] },
  { id: "person_identity", attributes: [ … 16 ] },
  …                                      // 15개 그룹 (src/domain/catalog/catalogs/prompt-order.ts)
  { id: "output",          attributes: ["output.aspect_ratio"] },
]
```

- 그룹 순서와 그룹 안 목록 순서가 곧 출력 순서입니다. 숫자가 없으므로 새 속성은 그 문장이 들어갈 자리에 ID를 끼워 넣기만 하면 됩니다. 다른 속성은 바뀌지 않습니다(테스트로 검증).
- 출력 순서와 UI는 분리되어 있습니다:
  - UI(탐색, 카테고리 페이지, Basic 목록)는 지금처럼 `order`와 카테고리를 씁니다.
  - 컴파일러는 `registry.promptAttributes()`를 씁니다. 레지스트리 생성 시 한 번 평탄화하므로 정렬을 반복하지 않습니다.
  - covers, 의미 단위 대체, 문장, 안전 검사 순서가 모두 이 순서를 따릅니다.
- 무결성: 모든 속성이 정확히 한 번 나와야 합니다. 누락, 중복, 알 수 없는 ID, 중복 그룹은 카탈로그 오류입니다. 따라서 출력 위치를 정하지 않은 새 속성은 카탈로그에 들어갈 수 없습니다(명시적·결정적).
- 출력 그룹 15개: 주제, 인물 기본 정보, 얼굴·이목구비, 피부·헤어·수염, 신체, 표정·인상·메이크업, 의상, 액세서리, 자세, 스타일, 구도·카메라, 장소, 분위기, 조명, 출력.

**호환성**
- `promptOrder`가 없는 카탈로그(형식 호환)는 예전처럼 `order` 순서로 출력합니다(테스트 확인).
- core 0.11.0의 목록은 0.10.0 출력 순서를 그대로 옮긴 것입니다.
- 변경 **전** 코드로 골든 데이터를 기록했습니다(`tests/fixtures/golden-prompt-order-0.10.0.json`). 카탈로그 3개(제품·E2E 테스트·확장 테스트) × 무작위 명세 120개 + 전체 속성 명세에 대해 프롬프트 해시와 문장 순서가 같습니다.
- ImageSpec에는 순서 정보를 저장하지 않습니다. 0.9.0·0.10.0 명세는 마이그레이션 기록 없이 그대로 열립니다.

## 2. TD-09 — 카테고리 초기화 및 복원 이력 (ADR-063)

**기록 내용**: 세션에서 최근 카테고리 초기화를 최대 **5개**까지 최신 순으로 기록합니다. 각 기록에는 다음이 들어갑니다:
- 대상 카테고리
- 지운 속성의 선택 객체 그대로: 변경 전 값, 프롬프트 포함·제외, 사용자 정의 값, 프리셋 출처, 적용되지 않는 값
- 순번(작업 순서)과 시각
- 초기화 뒤 사용자가 바꾼 속성 목록(`editedSince`)

하위 카테고리 포함 범위는 기존과 같습니다.

**복원 규칙**
- 기록마다 따로 복원합니다. 최근 기록뿐 아니라 이전 기록도 먼저 복원할 수 있습니다.
- 그 초기화가 지운 속성만 복원합니다. 다른 카테고리의 변경은 그대로입니다. ImageSpec 전체를 과거로 되돌리지 않습니다.
- 초기화 뒤 사용자가 같은 속성을 다시 설정했거나, **설정했다가 지운 경우**에는 현재 상태(미설정 포함)를 유지하고 “초기화 후 직접 수정해서 현재 상태를 유지한 항목”으로 알립니다.
- 적용되지 않는 값도 저장 상태 그대로 복원합니다(출력은 기존 규칙대로 하지 않음).
- 복원된 값도 컴파일 때 다른 저장값과 똑같이 안전 정책 검사를 받습니다. 예: 차단 대상 자유 입력을 초기화 후 복원하면 다시 출력이 보류됩니다(테스트).
- 변경 판정은 리듀서 공통 처리 한곳에서 합니다. 동작 전후 선택 객체를 비교하므로 설정, 해제, 포함·제외, 프리셋 적용·되돌리기, 다른 초기화·복원이 같은 방식으로 기록됩니다.

**프리셋과의 관계**
- 초기화는 기존처럼 프리셋 변경 내역에 사용자 수정으로 기록됩니다.
- 초기화 뒤 적용한 프리셋 값은 복원보다 우선합니다.
- 복원은 프리셋을 다시 적용하지 않습니다. 이후 프리셋 되돌리기는 복원된 값을 건드리지 않습니다(테스트).

**UI**
- 기존 막대(최근 초기화 + “카테고리 초기화 되돌리기”)는 그대로 둡니다.
- 아래에 “이전 초기화 n개” 접이식 목록을 추가했습니다. 항목마다 카테고리, 값 수, 시각, “이후 n개 직접 수정 — 현재 값 유지”, 개별 되돌리기 버튼이 있습니다.
- 복원 결과 안내를 표시합니다.

**범위 밖**: 범용 Undo/Redo, 새로고침 후 유지, 무제한 이력, Sprint 3의 속성 잠금·프리셋 이력(TD-04). 전체 초기화, 전체 초기화 되돌리기, JSON 가져오기, 복구 적용은 명세 전체를 바꾸므로 이력을 비웁니다.

## 3. TD-10 — 속성 간 충돌 진단 (ADR-064)

**분류**: 규칙 필드 `basis`를 추가했습니다.
- **의미 충돌**(`contradiction`, 경고): 두 설정의 의미가 서로 반대입니다.
- **관례와 다름**(`convention`, 정보): 일반적인 촬영·조명 관례와 다르지만 정당한 표현입니다. 물리적 현실성을 강제하지 않습니다.

두 종류 모두 비차단입니다. 값을 바꾸지 않고, 자동 정리 버튼도 없으며, 출력도 그대로입니다. 안전 검사와는 독립적이고, 차단된 명세에서도 진단은 따로 표시됩니다.

**조건 `numberIn`**: 수치 속성이 **설정되어 있고** 범위 안일 때만 참입니다. 미설정 슬라이더의 표시 위치는 추론하지 않습니다.

**추가 규칙 24개** (기존 90개 → 114개)

| 분류 | 규칙 |
|---|---|
| 얼굴 (의미 충돌) | 둥근형 + 얼굴 길이 긺(≥4), 직사각형 + 얼굴 길이 짧음(≤2) |
| 눈 (의미 충돌) | 둥근 눈 + 눈 높이 낮음(≤2), 가로로 긴 눈 + 눈 너비 좁음(≤2) |
| 코 (의미 충돌) | 들린 코 + 코끝 각도 아래로(≤2) |
| 입술 (의미 충돌) | 얇은 + 두 입술 두께 모두 도톰(≥4), 도톰한 + 두 입술 모두 얇음(≤2), “윗입술이 더 도톰” + 윗입술 얇음·아랫입술 도톰, 그 반대 |
| 신체 (의미 충돌) | 근육질 + 근육량 적음, 통통한 + 체지방 적음, 가녀린 + 체지방 많음, 모래시계형 + 허리·골반 대비 낮음, 치비 + 5등신 이상 |
| 표정 (의미 충돌) | 무표정 + 다른 감정, 무표정 + 감정 강도 강함(≥4), 입 다묾 + 입을 벌린 미소 |
| 카메라 (관례) | 조리개 f/1.4–f/2 + 깊은 피사계 심도(≥4), f/11–f/22 + 얕은 피사계 심도(≤2), 망원 + 과장된 원근감, 광각·초광각·어안 + 압축된 원근감 |
| 조명 (관례) | 부드러운 빛 + 뚜렷한 그림자 경계(≥4), 딱딱한 빛 + 부드러운 그림자 경계(≤2), 높은 명암 대비 + 그림자 없음 |

- 기존 규칙 `sky-light-in-studio`(스튜디오 + 하늘 빛 프리셋)는 관례 차이로 분류만 했습니다. 심각도 warning은 그대로입니다. 다른 기존 충돌 규칙은 기본값인 의미 충돌로 표시됩니다.
- 기존 규칙과 중복하지 않았습니다:
  - 렌즈 ↔ 초점 거리, 자세 ↔ 동작은 기존 규칙이 있습니다.
  - 의복 종류 ↔ 세부는 적용 가능성이 이미 처리합니다.
- 독립 축(눈 모양 ↔ 크기, 눈썹 모양 ↔ 각도)과 수치 대 수치 비교(상·하체 길이)는 추가하지 않았습니다.
- 경고 문구 예: “선택된 코 모양(들린 코)과 코끝 각도(아래로) 설정의 표현이 서로 충돌할 수 있습니다.”, “선택된 렌즈 종류(망원)와 과장된 원근감의 조합은 일반적인 사진 촬영 관례와 다를 수 있습니다.” 해결 안내는 권장만 하고 변경을 강제하지 않습니다(“의도한 표현이라면 그대로 두어도 됩니다”).
- 확인 편의:
  - 관련된 모든 필드에 안내가 붙습니다.
  - 필드 안내에 “관련 설정: 코끝 각도 (코)”처럼 다른 속성과 그 페이지를 표시합니다.
  - 미리보기 안내에도 나옵니다. 의미 충돌(경고)은 탐색 트리와 모바일 도구 모음의 경고 수에 포함되고, 관례 안내(정보)는 포함되지 않습니다(경고 수 과장 방지).
  - 규칙 하나는 진단 하나만 만듭니다. 같은 원인을 두 규칙이 중복 경고하지 않도록 규칙 범위를 나눴습니다(테스트에서 규칙마다 “정확히 그 규칙 하나”를 확인).
- 제외·미적용·사용자 정의 값은 기존 규칙과 같이 저장값 기준으로 판단합니다.

## 9. 개발 중 판단 사항

- 출력 순서는 숫자 대신 ID 목록으로 표현했습니다. 숫자 필드(그룹 + 그룹 내 번호)도 검토했지만, 그룹 안에서 다시 번호 재조정 문제가 생깁니다. 목록이 “명시적이고 결정적”이라는 요구에 더 맞습니다.
- 출력 위치를 모든 속성에 의무화했습니다(누락 시 카탈로그 오류). 자동 배치(미등록 속성을 끝에 붙이기)는 실수로 순서가 바뀌는 것을 숨기므로 택하지 않았습니다. 테스트 카탈로그만 예전 `order` 위치에 배치하는 도우미를 씁니다.
- 출력 그룹 ID는 기존 ID 규칙(소문자·밑줄)을 따랐습니다(`person_face` 등).
- 이력 개수는 5개로 정했습니다. 세션 안에서 연속 작업을 되돌리기에 충분하고, 목록이 짧아 무엇을 되돌리는지 알기 쉽습니다.
- “설정했다가 지운” 속성은 복원하지 않습니다. 사용자의 마지막 결정(미설정)을 우선합니다. 기존 동작은 미설정이면 복원했으므로 이번에 엄격해진 부분입니다.
- 관례 규칙의 심각도는 info, 의미 충돌은 warning입니다. 기존 규칙의 심각도는 바꾸지 않았습니다. 바꾸면 모바일 경고 수 등 기존 동작이 달라지기 때문입니다.
- 신체 규칙 추가는 ADR-052의 “신체 규칙 없음”을 이 범위에서 대체합니다. 지시서가 신체 형태·비율을 검토 대상으로 정했기 때문입니다. 신원 속성은 참조하지 않습니다.
