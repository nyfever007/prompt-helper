## 1. TD-11 최종 판단 — 부분 해결 유지

자세한 내용은 [PERFORMANCE.md](PERFORMANCE.md) §5–6에 있습니다.

- **CI 기록 정리**: Sprint 2-B.6 ~ 2-C.3의 CI 18회를 실행기 구분과 함께 표로 기록했습니다. 실행기는 같은 실행의 전체 테스트 시간으로 구분했습니다.
  - 빠른 실행기: 1.79–2.17초
  - 느린 실행기: 3.02–3.47초
  - 18회 모두 제한 5초 안에서 통과했습니다.
  - 서로 다른 실행기의 숫자만으로 개선이나 저하를 단정하지 않았습니다.
- **제품 성능과 테스트 비용 구분**:
  - 제품 쪽: 편집 1회당 컴파일 1회. 복잡한 명세(205개 값)도 **0.82ms**입니다.
  - 테스트 쪽: 500개 명세 테스트는 설계상 컴파일 1,000회(결정성 확인)와 깊은 비교를 합니다. 로컬 0.84–1.22초이며, 느린 CI 실행기에서는 3초를 넘습니다.
- 영향이 큰 단일 병목이 없어 추가 최적화는 하지 않았습니다(ADR-055 유지). 검증 범위, 표본 수, 안전 검사, 제한 시간은 바꾸지 않았습니다.
- **다시 검토할 조건**:
  - 느린 실행기에서 4.0초 초과
  - 5초 초과로 CI 실패
  - 2-D 이후 속성·규칙·신호가 10% 넘게 증가

## 5. 발견한 결함과 수정

1. **색상 팔레트 키보드(실제 브라우저에서만 발생)**
   - 증상: 화살표로 색을 고르면 바로 선택되지만, 이어서 Space를 눌러도 팔레트가 닫히지 않았습니다.
   - 원인: Chromium은 이미 선택된 라디오에서 Space가 click을 발생시키지 않습니다. jsdom(user-event)에서는 재현되지 않습니다.
   - 수정: 단일 선택 팔레트에서 현재 색에 Space 또는 Enter를 누르면 확정하고 닫은 뒤 토글로 포커스를 돌려줍니다.
   - 테스트: 컴포넌트 1개, 실제 브라우저 E2E.
2. **밝은 테마 성공 색 대비**: `--ok`가 연한 배경에서 3.85:1로 AA 미달이었습니다(성공 안내, 모바일 “정상” 표시). #237a35로 바꿔 4.7:1이 되었습니다.
3. **다크 테마 색상 견본 테두리**: 고정된 어두운 테두리 때문에 블랙 같은 어두운 견본이 배경에 묻혔습니다. 테마별 `--swatch-ring`(다크: 반투명 흰색)을 쓰도록 바꿨고, E2E에서 계산된 테두리 색을 확인합니다.
4. **머리말 부제**: 모든 모드에서 “— Basic Composer”(Sprint 1 문구)로 표시되던 것을 “하나의 이미지 명세를 Basic·Detailed에서 편집”으로 바꿨습니다.

데이터 손실, 안전 문제, 중대한 기능 장애는 발견되지 않았습니다.
