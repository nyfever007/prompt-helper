# 시각적 편집·추천 설계 원칙 (Sprint 2-D)

- 상태: **원칙 확정, 구현 전**. 2026-11-25 「Roadmap Update & Sprint 2-C.1」 지시서 §2·§4에 따라 문서화했습니다.
- 실제 시각 에셋과 추천 시스템 구현은 Sprint 2-D 승인 범위에서 시작합니다. Sprint 2-C.1에서는 구현하지 않았습니다.
- 상위 문서: [PROMPTER_MASTER_PLAN.md](../PROMPTER_MASTER_PLAN.md) §3·§8·§10. 시각 예시 제작 기준(TD-03): [catalogs/CATALOG_DESIGN_STANDARD.md](catalogs/CATALOG_DESIGN_STANDARD.md) §10.

## 1. 제품 방향

Prompter는 텍스트 기반 프롬프트 설계 도구에서 **시각적인 이미지 설계 도구**로 발전합니다. 사용자가 외형·카메라·조명의 전문 용어를 몰라도 원하는 이미지를 설계할 수 있게 하는 것이 목표입니다.

| 방향 | 내용 |
|---|---|
| Recommended Mode | 콘셉트 기반 추천 설정 |
| Visual Mode | 스케치와 시각적 예시로 선택 |
| Detailed Mode | 기존 상세 속성 편집 |

- 세 방향은 **하나의 ImageSpec**을 함께 편집합니다.
- 기존 Basic Editor와 Detailed Editor는 유지합니다.
- Visual Mode와 Recommended Mode의 최종 화면 구조는 Sprint 2-D에서 정합니다.

## 2. 시각적 선택

- 텍스트 선택지에 그 형태를 설명하는 시각적 예시를 붙일 수 있게 합니다.
- **우선 대상**:
  - 얼굴형, 눈 모양, 눈썹 모양, 코 모양, 입술 모양
  - 헤어스타일, 신체 비율, 의상 종류
  - 자세 및 행동, 카메라 앵글, 프레이밍
  - 조명 방향 및 효과
- 실사 이미지 제작은 기본 요구사항이 아닙니다. 간결한 선화, SVG, 실루엣, 설명용 도식을 먼저 사용합니다.
- 시각적 예시는 선택지 사이의 차이를 이해할 수 있을 정도면 충분합니다.

## 3. 시각 예시의 정확성

- 같은 속성의 선택지를 비교할 때는 다음 요소를 가능한 한 통일합니다:
  - 기준 인물 또는 오브젝트
  - 시점, 크기, 배율, 구도, 배경
  - 선 굵기, 표현 스타일
- 설명하려는 속성만 바꿉니다.
- 외모의 아름다움이나 우열을 평가하는 방향으로 시각 예시를 만들지 않습니다.
- 카탈로그 의미와 맞지 않는 임시 이미지는 완성된 제품 시각 예시로 쓰지 않습니다.
  - 기존 규칙은 그대로입니다: `examples[].status`가 `ready`가 아니면 “예시 이미지 준비 중”으로 표시합니다.
- 미성년자 예시와 노출 예시는 금지합니다. 출처·라이선스를 기록합니다. 두 규칙은 CATALOG_DESIGN_STANDARD §10을 따릅니다.

## 4. 동적 프리뷰

- 상대 슬라이더의 의미를 시각적으로 보여 줄 수 있게 합니다.
  - 예: 눈 크기, 눈 사이 간격, 눈썹 두께, 코 길이, 입술 두께, 얼굴 폭, 신체 비율
- 가능하면 여러 장의 이미지 대신 동적인 SVG를 사용합니다.
- 상대 슬라이더는 실제 측정값이 아닙니다. 기존 원칙대로 프리뷰도 의미 구간만 표현합니다.

## 5. 조합 프리뷰

- 얼굴형, 눈, 눈썹, 코, 입술 등 선택된 속성을 조합한 간단한 얼굴 스케치를 검토합니다.
- 이 기능은 사용자의 설정 의도를 설명하기 위한 것입니다. 실제 이미지 생성 모델의 결과를 예측하거나 재현한다고 안내하지 않습니다.
- 미설정 속성의 프리뷰용 표현(기본 모양)은 ImageSpec에 자동 저장하지 않고 프롬프트에도 추가하지 않습니다.
  - 기존 원칙 “표시된 위치는 값이 아니다”(슬라이더)와 같습니다.
- 시각적으로 표현할 수 없는 속성은 기존 텍스트 방식으로 편집할 수 있어야 합니다.

## 6. 추천 모드

- 초기에는 AI 없이 직접 설계한 추천 프리셋을 사용합니다. 제품 추천 프리셋의 내용은 별도 승인 대상입니다.
- 기존 프리셋 시스템을 재사용합니다: 계획 → 확인 → 적용, 적용 출처 추적, 되돌리기.
- 추천 항목을 고르는 것만으로 기존 설정을 덮어쓰지 않습니다. 적용될 값과 기존 설정의 변경 내용을 먼저 확인할 수 있게 합니다.
  - 현재 프리셋 대화상자의 “새로 설정 / 기존 값 변경 / 이미 같음 / 적용 안 됨” 구성과 같습니다.
- 사용자가 직접 선택한 값을 임의로 제거하거나 바꾸지 않습니다.
- 추천이 연령, 성별, 국적, 피부색, 신체 특징, 성적 표현을 불필요하게 추론하지 않습니다.

## 7. 편집 화면 UX 원칙 (Sprint 2-C.1 최종 승인에서 추가)

- 사용자가 함께 조작하는 속성은 가능한 한 가까이 배치합니다.
  - 예: 림 라이트 강도와 림 라이트 색상을 같은 하위 분류에 둡니다.
- 의미 분류의 정확성과 실제 편집 동선을 함께 고려합니다. 분류 이름이 정확해도 함께 바꾸는 값이 여러 페이지에 흩어지면 동선을 우선 검토합니다.
- 관련 속성의 적용 가능성과 비활성화 이유를 쉽게 확인할 수 있게 합니다.
  - 의존하는 속성과 같은 화면에서 “현재 선택에는 적용되지 않습니다(값 보존)” 같은 안내를 볼 수 있어야 합니다.
- 시각적 예시를 추가해도 화면이 불필요하게 길어지지 않게 합니다.
  - 색상 팔레트처럼 현재 값만 접어서 보여 주고, 요청할 때 펼치는 방식을 우선 검토합니다.

## 8. Sprint 2-C.1에서 확인한 확장 지점 (구현하지 않음)

Sprint 2-C.1 지시서 §6에 따라 현재 선택지 렌더링 구조를 점검했습니다.

| 표현 | 현재 구조 | 2-D에서 필요한 것 |
|---|---|---|
| 텍스트 | 칩·목록·드롭다운 컨트롤(`Controls.tsx`, `OptionPicker.tsx`) | 그대로 사용 |
| 색상 견본 | `ColorControl` — 2-C.1부터 접힌 현재 값 + 비모달 팔레트 | 그대로 사용 |
| 정적 시각 예시 | `CardsControl`과 `OptionDefinition.examples`(상태·출처·대체 텍스트), 확대 대화상자(2-C.1 모달 접근성 적용) | 에셋 표준(2-D.1)과 실제 자산 |
| SVG | `examples[].src`에 data URI SVG를 이미 쓸 수 있음(테스트 카탈로그 사례) | 동적 SVG(슬라이더 값 반영)용 컴포넌트 |
| 선택 상태 표시 | 모든 컨트롤이 `data-checked`와 네이티브 radio/checkbox로 표시 | 그대로 사용 |

- 시각 예시가 없는 선택지는 지금처럼 텍스트로 정상 사용할 수 있습니다. 카드 컨트롤은 “예시 이미지 준비 중”으로 정직하게 표시합니다.
- 이번 단계에서는 새 스키마, 빈 프레임워크, 추상화를 미리 추가하지 않았습니다.

### Sprint 2-C.2에서 확인한 사항

- 출력 순서(`promptOrder`), 카테고리 초기화 이력, 충돌 진단은 모두 ImageSpec 형식(0.3.0)과 값 형식을 바꾸지 않습니다.
  - 시각적 선택지, 슬라이더 연동 스케치, 얼굴 조합 프리뷰, 추천 프리셋은 텍스트 편집과 같은 저장값과 같은 컴파일 경로를 씁니다.
- 출력 순서가 UI 순서와 분리되었습니다. 2-D에서 시각 편집 화면의 배치를 바꿔도 프롬프트 순서는 바뀌지 않습니다.
- 충돌 진단은 설정된 값만 읽습니다(`numberIn`은 미설정 슬라이더를 추론하지 않음). 프리뷰용 기본 모양이 진단을 일으키지 않습니다.
- 미래 기능을 위한 추상화나 빈 구조는 추가하지 않았습니다.

## 9. Sprint 2-D 진입 준비 현황 (Sprint 2-C.4 점검)

이번 점검은 현황 기록만 합니다. 새 컴포넌트, 에셋 스키마, 추천 기능은 만들지 않았습니다.

| 영역 | 현재 구조 | 2-D에서 필요한 것 |
|---|---|---|
| 공통 속성 렌더링 | `WorkspaceField` → `AttributeField` → 컨트롤별 컴포넌트(`Controls.tsx`: 칩·카드·검색 목록·드롭다운·색상·슬라이더·수치·범위, `OptionPicker`, `QuantityControl`, `CustomEntries`). 어느 컨트롤을 쓸지는 카탈로그의 `control`이 정합니다 | 시각 선택 컨트롤 1종(카드 확장 또는 신규)을 같은 계약(선택·해제·제한·적용 불가 표시)으로 추가 |
| 시각 예시 표시 | `CardsControl`: `examples[]` 중 `status: "ready"`이고 `src`가 있는 것만 이미지로 표시합니다. 그 밖에는 “예시 이미지 준비 중”입니다. 영어 용어와 설명을 함께 보여 줍니다 | 제품 카탈로그에 준비된(`ready`) 예시는 **0건**(스타일 프리셋의 자리표시자 1건, 테스트 카탈로그의 data URI SVG 1건만 있음) |
| 에셋 메타데이터 | `VisualExampleSchema`: `id`, `status`(placeholder/ready), `src`, `alt`(다국어), `provenance`(출처·라이선스·작성일) | 비교 기준(같은 인물·시점·배율), 테마 대응, 크기 등 에셋 표준(2-D.1, TD-03) |
| 예시 확대 | `CardsControl`의 확대 대화상자 — 공통 `ModalDialog`(초기 포커스, Tab 순환, Escape, 포커스 복귀) | 그대로 사용 |
| SVG·정적 이미지 | `<img src>`로 data URI SVG와 정적 경로를 모두 쓸 수 있습니다 | 테마를 따르는 SVG는 `<img>`로는 `currentColor`를 상속하지 못합니다. 인라인 SVG 컴포넌트나 테마별 에셋 중 하나를 선택해야 합니다(아래 조건) |
| 상대 슬라이더 ↔ 프리뷰 | `SliderControl`은 `value`와 의미 구간(`bands`)을 받으며, 미설정이면 값이 없습니다(표시 위치는 저장하지 않음) | 슬라이더 값(또는 미설정)을 받는 순수 SVG 컴포넌트. 미설정이면 중립 모양을 보여 주되 저장하지 않음 |
| 공통 ImageSpec | Basic, Detailed, Precision 요약이 같은 명세·적용 조건·컴파일러를 씁니다. 출력 순서는 `promptOrder`(UI와 분리) | 시각 편집도 같은 `setValue`/`clear`만 사용 |
| 프리셋 | 계획 → 확인 → 적용, 출처(`origin`), 마지막 1회 되돌리기, 사용자 수정 보호 | 추천 프리셋(2-D.5)이 그대로 재사용. 제품 프리셋 내용은 별도 승인 |
| 테마·접근성 | 색상 토큰과 다크 모드(`prefers-color-scheme`), 텍스트 대비 WCAG AA 자동 검사(`theme-contrast` 테스트), 키보드·포커스 회귀 E2E | 아래 조건 |

**시각 에셋의 테마·접근성 조건** (Sprint 2-C.4에서 정함)
1. 선화·도식은 두 테마에서 모두 읽혀야 합니다.
   - 선과 면 색은 `currentColor` 또는 CSS 토큰(`--text`, `--muted`, `--accent`)을 따릅니다. 인라인 SVG이거나, 테마별 에셋 2벌을 둡니다.
   - 배경을 투명하게 둘 경우, 어두운 배경에서 어두운 선이 사라지지 않는지 확인합니다.
2. 선과 배경의 대비는 3:1 이상입니다(WCAG 1.4.11 비텍스트 대비). 선택 상태는 색만이 아니라 테두리·체크 표시로도 구분합니다(TD-18과 함께).
3. 모든 예시에는 의미를 설명하는 `alt`를 둡니다. 장식용이면 빈 alt를 씁니다. 예시가 없거나 로딩에 실패해도 텍스트 선택은 그대로 동작합니다.
4. 색상 견본처럼 어두운 대상이 어두운 배경에 놓이면 테마별 테두리(`--swatch-ring`)를 둡니다.
5. 에셋은 앱 JS 번들에 넣지 않습니다. 정적 파일이나 지연 로딩으로 분리하고, 추가 전후 성능 기준선(`docs/PERFORMANCE.md`)을 비교합니다.

## 10. 에셋 표준과 첫 적용 (Sprint 2-D.1, TD-03)

- **형식**: 정적 SVG 선화. `public/visual/<영역>/<속성>/<선택지 ID>.svg`에 두고 카드 컨트롤이 `loading="lazy"`로 필요한 페이지에서만 불러옵니다. JS 번들에는 들어가지 않습니다.
- **연결**: 기존 `examples` 메타데이터를 그대로 씁니다(`status: "ready"`, `src`, 한·영 `alt`, `provenance`). 새 스키마나 시각 편집 전용 데이터는 없습니다. 속성은 `cards` 컨트롤을 쓰며, 값·ID·프롬프트 출력은 같습니다.
- **제작**: `scripts/generate-visual-assets.mjs`가 코드로 생성합니다(결정적). 같은 속성 안에서는 캔버스(160×120), 배율, 선 굵기, 중립 회색 면, 비교하지 않는 이목구비를 모두 같게 하고 **비교 대상만** 바꿉니다.
  - 피부색, 성별, 연령, 헤어, 메이크업을 넣지 않습니다.
  - 아름다움을 평가하지 않으며, 모델의 결과를 예측하지 않습니다.
  - 눈 모양은 눈꼬리 각도(별도 속성)를 수평으로 고정합니다. 눈썹 모양은 같은 기준 눈 위에 그립니다.
- **테마**: SVG 안의 CSS 변수를 `prefers-color-scheme`으로 바꿉니다(이미지로 넣은 SVG도 페이지의 색 구성을 따름). 선은 카드 배경 대비 3:1 이상입니다.
- **UI**:
  - 준비된 예시는 이미지, 자리표시자 예시는 “예시 이미지 준비 중”, 예시가 없는 선택지는 텍스트 카드로 표시합니다.
  - 선택은 기본 라디오·체크, ✓ 표시, 강조 테두리로 보여 줍니다(색만으로 구분하지 않음).
  - 확대 버튼은 선택지 이름으로 구분합니다(“하트형 예시 크게 보기”).
  - 이미지를 불러오지 못하면 텍스트 카드로 남습니다.
- **적용**: 얼굴형 8, 눈 모양 4, 눈썹 모양 6 = 선화 18개(합계 72KB). 얼굴 조합 프리뷰와 다른 영역은 후속 단계(2-D.2 이후)에서 합니다.
- **기능 요소 대비(TD-18)**:
  - 입력창, 선택 목록, 검색창, 칩, 카드, 버튼의 경계는 `--border-strong`을 씁니다(밝은 테마 #85827b, 다크 #77756e — 모든 배경 대비 3:1 이상, 테스트로 확인). 체크된 목록 행에는 강조 막대를 둡니다.
  - 패널, 구분선 같은 장식용 테두리는 그대로 둡니다.

## 11. Face Builder와 동적 프리뷰 (Sprint 2-D.2)

- **한 개의 그림 모델**: `src/visual/face-sketch.ts`가 정면·옆모습을 그립니다. 정적 카드(`scripts/generate-visual-assets.mjs`)와 실시간 스케치가 같은 모델을 쓰므로 카드와 Face Builder의 모양이 일치합니다. 카드는 같은 얼굴의 해당 부위를 같은 범위로 잘라 보여 주고, 비교하는 특징만 바뀝니다.
- **데이터**: 별도 얼굴 모델이 없습니다. ImageSpec → 그림 값 매핑(`faceSketchState`)은 읽기 전용입니다. 미설정 항목은 중립 형태로 그리지만 저장·출력하지 않습니다.
- **상태 표시**: 프롬프트에서 제외되었거나 현재 적용되지 않는 설정은 그리지 않고 목록으로 알립니다(스케치 = 프롬프트가 설명하는 내용). 사용자 지정 값과 그림이 없는 특징(광대, 볼, 대칭, 눈 깊이, 속눈썹, 턱끝 모양 등)은 “그리지 않는 설정”으로 표시합니다.
- **옆모습**: 콧대 모양·높이, 코끝 각도, 턱 돌출처럼 정면에서 보이지 않는 특징을 위해 작은 옆모습을 함께 그립니다. 코 전체 모양 카드는 옆모습과 정면을 나란히 보여 줍니다.
- **슬라이더 프리뷰**: 그림으로 의미가 분명한 상대 슬라이더(25개)에만 붙입니다. 그 슬라이더 자신의 값은 프롬프트에서 제외되어도 의미 설명을 위해 그립니다.
- **한계**: 의미 설명용 선화이며 이미지 모델의 결과를 예측하거나 보장하지 않습니다. 턱선은 카드에만 있고 조합 스케치에는 그리지 않습니다(얼굴형과 같은 윤곽을 다른 방식으로 바꾸기 때문). 피부색·헤어·메이크업은 그리지 않습니다.
