## ADR-001 독립 저장소 — **확정**
- 결정: `~/projects/promptmaker`를 독립된 git 저장소로 초기화했습니다(`git init -b main`). WHY 저장소는 열람하거나 수정하지 않았습니다.
- 근거: 이 폴더는 원래 홈 디렉터리(`~`) 전체를 추적하는 상위 git 저장소 안에 있었습니다. 계획서 §15 "Fresh prompter repo"를 충족하려면 별도 저장소가 필요했습니다.
- 비고: 커밋은 하지 않았습니다(사용자 승인 대기). 폴더 이름은 계획서의 `prompter/` 대신 기존 `promptmaker`를 유지했고, 패키지 이름은 `prompter`입니다.

## ADR-002 기술 스택 — **채택(검토 필요)**

  - ESLint 10은 `eslint-plugin-react`(eslint-config-next 의존성)의 지원 범위(`^9.7`까지) 밖이라 9.39를 썼습니다.

## ADR-003 ImageSpec 형태: 속성 ID로 찾는 단일 selections 맵 — **채택(검토 필요)**
- 결정: `selections: Record<AttributeId, AttributeSelection>`. 속성 ID는 점으로 구분한 경로입니다(`subject.kind`, 향후 `person.skin.moles`).
- 대안 A: 계획서 §5 예시처럼 도메인별 중첩 타입 객체(`person.body.bust`)를 쓰는 방식. 새 속성을 추가할 때마다 스키마, 컴파일러, UI 타입을 함께 바꿔야 해서 "카탈로그 확장 시 핵심 코드 무수정" 요구와 충돌합니다.
- 대안 B: unset을 `{ state: "unset" }` 항목으로 명시하는 방식. unset 표현이 두 가지(키 없음, unset 항목)가 되어 정규형이 흐려집니다.
- 근거: unset이 **키 없음** 한 가지로만 표현됩니다. 맵 구조라 모든 속성 쌍의 독립성을 일반적으로 테스트할 수 있습니다. 계층 구조는 ID 경로와 카탈로그의 `domain`/`groupId`가 맡습니다.
- 영향: 계획서 §5 JSON 예시와 형태가 다릅니다(계획서도 "illustrative, not final schema"라고 명시).

## ADR-004 자기 기술형 값과 2단계 검증 — **채택**
- 결정: 값에 `kind`(single, multi, number, range, text)를 포함합니다. 검증은 1단계 구조 검증(카탈로그 없이 Zod)과 2단계 의미 검증(카탈로그 기준)으로 나눕니다.
- 근거: 카탈로그를 바꾸거나 버전이 달라도 파일을 구조적으로 읽을 수 있고, 어떤 속성·옵션이 문제인지 정확히 보고할 수 있습니다.
- 정책: 가져오기와 복원은 전부 아니면 전무입니다. 오류가 하나라도 있으면 거부하고 현재 명세를 유지합니다. 카탈로그 **ID**가 다르면 오류, **버전**만 다르면 경고입니다.

## ADR-005 기본값은 "제안"일 뿐 — **확정(계획서 원칙 2)**
- 결정: `AttributeDefinition.defaultValue`는 UI가 "권장 기본값 사용" 버튼으로 제안하는 값입니다. `createEmptySpec`과 컴파일러는 이 값을 적용하지 않습니다. 사용자가 선택하면 일반 선택과 똑같이 저장됩니다.
- 근거: unset과 명시적 기본값을 데이터 수준에서 구분합니다(테스트 3번).

## ADR-006 결정론적 규칙 기반 컴파일러 — **채택**
- 결정:
  - 출력 순서는 카탈로그의 `(order, id)` 순서입니다. 객체 키 순서에 의존하지 않으며, 복수 선택도 카탈로그 순서로 출력합니다.
  - 템플릿 치환은 `split("{value}").join(…)`으로 합니다. 사용자 텍스트의 `$&`, `{value}` 등이 해석되지 않도록 하기 위해서입니다.
  - 공백 정규화와 문장 종결 부호 보정은 **출력에만** 적용합니다. 저장된 명세는 입력한 그대로 유지됩니다.
  - `COMPILER_VERSION`, adapter id/version, catalog id/version, spec 스키마 버전을 출력 메타에 포함합니다.
  - adapter 경계: `PromptAdapter`(텍스트 형식)와 `ImageProviderAdapter`(API 호출)를 분리합니다.
  - generic-en adapter는 fragment마다 한 문장을 만들고 중요도는 표현하지 않습니다. 중요도가 설정되어 있으면 "무시됨" 진단을 보고합니다(계획서 §6 "Explain unsupported controls").
- 근거: 계획서 §6, 지시문 §6.

## ADR-007 적용 불가 선택값은 유지하되 컴파일하지 않음 — **채택**
- 결정: `appliesWhen`을 만족하지 않는 속성(예: 피사체를 풍경으로 바꾼 뒤의 표정)도 명세에 그대로 둡니다. 이 값은 컴파일에서 제외하고 `selection.inactive` 진단과 UI 안내를 표시합니다.
- 근거: "한 속성의 변경이 다른 속성을 변경하지 않는다"는 원칙을 지키고, 피사체를 되돌렸을 때 사용자가 다시 입력하지 않아도 됩니다.

## ADR-008 로컬 저장 — **채택**
- 결정: `localStorage` 키 `prompter:v1:workspace`에 `{ kind, storageVersion: 1, savedAt, spec }` envelope로 저장합니다. 불러올 때 전체를 다시 검증하고, 실패하면 원본을 `…:corrupt-backup`에 보관한 뒤 빈 명세로 시작합니다.
- 모드와 UI 언어는 `prompter:v1:ui`에 따로 저장합니다. 보기 설정은 명세에 포함하지 않습니다.
- 저장소는 `KeyValueStore` 인터페이스로 주입할 수 있습니다(테스트용 메모리 저장소, 향후 IndexedDB나 서버 저장소).
- 자동 저장은 hydration 상태(ref 아님)를 기준으로 동작합니다. 복원 전의 빈 명세가 저장 데이터를 덮어쓰지 않게 하기 위해서입니다.

## ADR-009 카탈로그는 TypeScript 데이터 + 로드 시 Zod 검증 — **채택**
- 결정: `src/domain/catalog/catalogs/core.ts`(`satisfies CatalogInput`). 카탈로그 파일 형식 버전(`formatVersion`)과 내용 버전(`version`)을 분리합니다.

- 규칙: 옵션이나 속성 ID를 삭제·변경하거나 프롬프트 문구를 바꾸면 `version`을 올립니다. ID 변경 마이그레이션은 아직 없습니다(미해결 Q4).

## ADR-016 ImageSpec 0.1.0 유지 — **확정 (승인됨)**

## ADR-017 스타일: Basic은 단일 프리셋, 내부는 독립 축 — **확정 (#1 수정 반영)**
- 결정: Basic UI는 검색 가능한 `style.preset` 하나만 노출합니다. 내부에는 독립 축 속성 `style.medium`·`realism`·`technique`·`movement`·`aesthetic`을 Detailed tier로 정의했습니다. 각 프리셋은 `classification`으로 축 값을 **참고 정보로만** 가집니다.
- 규칙: 분류 정보는 다른 속성을 설정하지 않고 프롬프트 문장도 만들지 않습니다(테스트). UI는 "프리셋을 고르면 ‘이미지 스타일’ 항목만 설정됩니다"라고 안내합니다.
- ID 변경: 0.1.0의 `style.visual`을 `style.preset`으로 바꿨습니다(사유: 스타일이 여러 축으로 확장되어 Basic 목록이 프리셋임을 명확히 함). 마이그레이션으로 자동 변환되고 사유가 기록됩니다.
- 보류: 축 편집기와 대규모 카탈로그 확장은 Sprint 4입니다.

## ADR-018 조명: 빠른 프리셋 + 독립 속성 — **확정 (#2 수정 반영)**
- 결정: Basic은 `lighting.preset`(12종)만 노출합니다. 내부에 `lighting.source`·`direction`·`softness`·`intensity`·`color_temperature`·`contrast`를 독립 속성(Detailed tier)으로 정의했습니다.
- 프리셋을 적용하면 **`lighting.preset` 하나만** 바뀝니다. 프리셋이 의미하는 조명 속성은 `classification`으로 표시만 하며 적용하지 않습니다. 관련 없는 속성은 바뀌지 않습니다(테스트).
- 대안(기각): 프리셋 적용 시 6개 축 속성에 값을 써 넣는 "패치형"은, Basic에서 보이지 않는 속성을 바꾸게 되어 "선택하지 않은 속성 자동 확정 금지" 원칙과 충돌합니다. 패치형 프리셋(계획서 §5 Preset)은 변경 목록을 보여주는 UI와 함께 Detailed 단계에서 재검토합니다.

## ADR-019 안전 정책 계층 — **확정 (승인 범위), 한계 명시** (현재 정책 0.3.0: ADR-065, [SAFETY_POLICY.md](SAFETY_POLICY.md))
- 구조: `src/domain/safety`. 카탈로그 검증과 독립되어 있고, 정책 데이터에 버전이 있습니다(`prompter.baseline@0.1.0`).
  - 신호(signal): 선택지 `policyTags`와 어휘(영어는 단어 경계, 한국어는 부분 문자열 + 예외 구문, 나이 숫자 정규식)에서 얻습니다.
  - 규칙: 신호 그룹의 AND/OR 조합입니다.
- 차단 범주: ① 미성년자 또는 나이가 모호한 표현 + 성적·노출 표현(승인된 보수적 규칙 #7) ② 노골적 성적 내용 ③ 나체.
- 성적 신호가 **아닌 것**: 체형(`body.*`), 의상 핏(`fit.*`), 노출 범위(`coverage.*`), 수영복, "shirtless", "curvy" 등. 성인의 매력 표현("sexy", "sensual", "lingerie")은 단독으로는 허용하고, 미성년 신호와 결합할 때만 차단합니다.
- 적용 경로: 컴파일된 출력(선택지 태그 + 모든 fragment + adapter 최종 문자열)을 검사합니다. 가져오기와 복원은 데이터를 보존하고, 그 명세의 출력도 같은 관문으로 차단됩니다. 미리보기, 복사, .txt 내보내기는 `getPromptOutput`만 사용합니다. 명세 JSON 저장과 내보내기는 허용합니다(승인 #8).
- 원본 보존: 사용자 텍스트를 고쳐서 통과시키지 않습니다.
- **한계 (검증되지 않은 범위)**:
  - 의미 이해가 없어 은어, 우회 철자(s3xy), 띄어쓰기 변형, 다른 언어(일본어·중국어 등), 문맥(예: 의학·예술 맥락)을 판별하지 못합니다.
  - 한국어 부분 문자열 매칭에서 오탐이 생길 수 있습니다. 확인된 경우는 예외 목록으로 처리했지만 모두 찾았다는 보장은 없습니다.
  - "girl"/"소녀" 등 나이가 모호한 단어에 대한 보수적 규칙이 성인 대상 표현을 차단할 수 있습니다(의도된 트레이드오프).
  - 이미지 자체는 검사하지 않으며, 어떤 이미지 provider의 정책 준수도 보장하지 않습니다.
  - 폭력, 실존 인물, 혐오 등 다른 범주는 아직 정의하지 않았습니다(구조만 있음).

## ADR-020 언어 정책 — **확정**
- 한국어가 기본 UI 언어이고 영어 UI를 유지합니다. 구조화된 선택은 영어로 컴파일합니다.
- 자유 입력은 명세에 **원문 그대로** 보존합니다. 출력에서는 공백만 정리하고 번역하지 않습니다.
- 출력에 비라틴 문자 체계(한글, 한자, 가나, 키릴 등)가 섞이면 `prompt.mixed_language` 경고를 표시합니다. 라틴 문자를 쓰는 다른 언어(프랑스어 등)는 감지하지 못합니다(한계).
- AI 번역과 다듬기는 Sprint 5로 보류합니다.

## ADR-021 카탈로그 ID 마이그레이션 — **확정 (승인됨)**
- 카탈로그에 `fromVersion → toVersion` 단계별 `renameAttribute`/`renameOption`과 사유(다국어)를 선언합니다. 레지스트리가 체인의 연속성, 진행 방향, 최종 대상 존재를 검증합니다.
- 적용 원칙: 선언된 변경만 적용합니다. 대상이 이미 있으면 덮어쓰지 않고 충돌로 보고합니다. 알 수 없는 속성·선택지는 추측해 연결하거나 삭제하지 않고 복구 단계에서 사용자에게 보여줍니다.
- 기록: 적용된 변경마다 (변경 전 → 변경 후, 버전, 사유)를 남깁니다. 알림으로 표시하고, 로컬 복원 시 `prompter:v1:migration-log`에 저장하며, 변경 전 원본은 `:pre-migration-backup`에 둡니다.
- 마이그레이션 자체는 결정론적이고 무손실인 ID 변경이므로 확인 없이 적용하고 알립니다. 손실이 생길 수 있는 복구만 확인을 받습니다(ADR-022).

## ADR-022 사용자 확인 기반 부분 복구 — **확정 (승인됨)**
- `analyzeSpecInput` → `valid | recoverable | invalid`. recoverable이면 **제안된 명세**와 함께 제외 항목 목록(경로, 원본 값, 사유)을 반환합니다.
- 로컬 복원: 원본을 `:corrupt-backup`에 보관합니다. 사용자가 결정하기 전에는 자동 저장을 중지합니다(원본 키를 덮어쓰지 않음). 선택지는 [제외하고 복구] / [원본 다운로드] / [복구하지 않고 새로 시작]입니다.
- 가져오기: [제외하고 가져오기 (현재 작업 대체)] / [원본 다운로드] / [가져오기 취소]이며, 원본 파일은 변경하지 않습니다.
- 다중 선택 값에 무효한 선택지가 하나라도 있으면 **값 전체를 제외**합니다(일부만 고치는 것은 의도를 바꾸는 행위로 판단).

## ADR-023 초기화 되돌리기 — **확정 (#10 수정 반영)**
- 초기화 직전 명세의 스냅샷 1개를 세션 메모리에 보관합니다. 이후 편집해도 스냅샷은 유지됩니다.
- 복원할 때 현재 작업이 있으면 덮어쓴다는 확인을 받습니다. 빈 명세를 초기화하면 기존 스냅샷을 지키고, 다음에 내용이 있는 상태에서 초기화하면 스냅샷을 교체합니다.
- 새로고침하면 사라지며, 전체 이력과 영구 버전 관리는 후속 스프린트로 보류합니다.

## ADR-024 Basic 화면 구성 — **채택**
- 카탈로그 그룹 순서대로 섹션을 만듭니다. 각 그룹은 `prominence: primary` 항목을 먼저 보여주고, `secondary`는 "추가 설정"으로 펼칩니다. 설정된 값이 있으면 자동으로 펼쳐집니다.
- UI를 단순화하려고 데이터 표현력을 제한하지 않습니다. 화면 배치는 데이터(`prominence`, `searchable`, `tier`)로 결정합니다.
- 적용되지 않는 속성과 선택지는 숨기되, 이미 선택된 값은 점선과 안내로 표시하고 남겨 둡니다.
- 알림: 복원·성공·전환 알림은 자동으로 사라지고, 오류·마이그레이션·복구 결정은 사용자가 닫을 때까지 유지합니다.

## ADR-025 로컬 검증 명령과 CI — **채택 (원격 미연결)**
- `pnpm verify` = `pnpm check` + `pnpm test:e2e`.
- `.github/workflows/ci.yml`을 준비했습니다. Sprint 1 완료 후 사용자 지시로 원격 저장소(`origin` = github.com/nyfever007/prompt-helper)를 연결하고 push했으며, 이후 GitHub Actions에서 실행됩니다.
- 이 개발 환경의 명령 sandbox 안에서는 Chromium이 시작되지 않아(macOS Mach 포트 권한), E2E는 sandbox 밖에서 실행했습니다. 일반 개발자 환경과 CI에는 해당하지 않습니다.

## ADR-028 ImageSpec 0.2.0과 프리셋 출처 — **확정 (D2)**
- `AttributeSelection.origin { presetId, presetVersion }`은 `source: "preset"`일 때만 허용됩니다(스키마 refine). 직접 편집하면 `source: "user"`가 되고 origin은 사라집니다.
- **영구 출처**(source, presetId, presetVersion)는 ImageSpec에 저장합니다. **세션 프리셋 트랜잭션**(적용 전·후 선택값과 출처, 실제 변경된 속성, 적용 이후 사용자 편집 여부)은 세션 메모리에만 두고 마지막 1회 되돌리기에만 씁니다.
- 되돌리기는 값 비교가 아니라 `userEdited` 기록으로 판단합니다. 적용 후 사용자가 바꿨다가 같은 값으로 되돌린 속성도 보호됩니다(테스트).
- 마이그레이션 0.1.0 → 0.2.0은 버전 번호만 바꾸는 무손실 변환입니다(Sprint 0·1 실제 데이터로 검증).
- **한계**: 이 버전에서 내보낸 JSON(0.2.0)은 Sprint 0·1 앱이 읽지 못합니다(이전 버전 호환 미지원).

## ADR-029 의미 단위와 프리셋 우선순위 컴파일 — **확정 (D3 수정안)**
- 프리셋 문구를 `parts`로 분해할 수 있습니다. 각 의미 단위(`{ axis, values, text }`)는 다른 속성(축)의 값을 명시합니다. 레지스트리는 **parts를 렌더링한 결과가 원래 text와 정확히 같아야** 통과시키므로, Sprint 1 프롬프트가 보존됩니다.
- 컴파일 2단계: (1) 실제로 출력할 속성을 결정하고, (2) 축 속성이 직접 설정되어 출력되면 프리셋 문구에서 그 단위를 뺍니다.
  - **같은 의미**(`equivalent`): 한 번만 출력하고 직접 설정 쪽에 귀속합니다. 프리셋 fragment의 `takenOverBy`로 추적합니다.
  - **같은 속성, 다른 값**(`override`): 직접 선택이 우선하고, 프리셋의 해당 표현을 대체하며, info 진단으로 알립니다. 프리셋 선택 자체는 삭제하지 않습니다.
  - **다른 축**: 서로 독립입니다. 예를 들어 골든아워와 차가운 컬러 그레이딩은 충돌이 아닙니다(fixture 테스트).
  - **실제 충돌**: 카탈로그 규칙(예: `backlight-vs-direction`)으로 경고와 해결 안내를 표시하고, 자동 수정하지 않습니다. 안전 차단과는 구분합니다.
- 문자열 비교나 삭제에 의존하지 않습니다. 분류 정보(classification)는 메타데이터일 뿐 출력에 쓰이지 않습니다. 단위 판단은 `parts`의 구조화된 축과 값으로 합니다.
- 모델별 표현(`byAdapter`)이 있는 문구는 불투명하게 취급하고 단위를 대체하지 않습니다(한계).

## ADR-030 복합 프리셋 — **확정 (D4 포함)**
- 프리셋은 전체 명세를 바꾸지 않는 **부분 패치**입니다.
- `planPreset`: 각 패치를 new / change / same / inapplicable / restricted로 분류하고, 건드리지 않는 기존 설정 목록과 적용 후 생길 규칙 충돌을 계산합니다. 명세는 바뀌지 않습니다.
- 적용: [기존 값을 덮어쓰고 적용](change가 있을 때만 보이는 명시적 선택) / [비어 있는 항목만 적용] / [취소].
- 적용 불가와 제한된 패치는 건너뛰고 목록으로 보여 줍니다(D4).
- same으로 분류된 사용자 값은 덮어쓰지 않으므로 사용자 소유로 남습니다.
- 제품용 복합 프리셋은 없습니다(별도 승인 대상). 테스트 카탈로그에만 4개 있습니다.

## ADR-031 테스트 카탈로그 격리 — **확정 (D7)**
- **일반 프로덕션 빌드**(`pnpm build`, CI의 build 단계):
  - `next.config`의 `env`가 `PROMPTER_E2E_FIXTURES`를 빌드 시점에 `"0"`으로 치환합니다.
  - 그래서 `/e2e-fixtures` 페이지의 테스트 카탈로그 import가 죽은 코드가 되어 번들에서 제거되고, 페이지는 항상 404입니다.
  - URL, 쿼리 문자열, 클라이언트 설정으로는 켤 수 없습니다. 서버 실행 시 환경 변수를 주어도 켜지지 않습니다(이미 상수로 치환됨).
- **E2E 전용 빌드**(Playwright webServer):
  - `PROMPTER_E2E_FIXTURES=1`, `PROMPTER_DIST_DIR=.next-e2e`로 별도 폴더에 빌드합니다.
  - 테스트 페이지는 노란 "테스트 전용" 배너를 표시합니다.
  - 저장 키 앞에 `prompter-e2e-fixture:`를 붙여 실제 사용자 데이터와 격리합니다.
- **검증**: `pnpm verify:isolation`(CI 포함)이 일반 빌드 결과물 전체에서 테스트 카탈로그 흔적을 찾고, 실행 중인 서버의 `/e2e-fixtures` 응답이 404인지 확인합니다. 대조 확인으로 E2E 빌드에는 흔적이 있음을 확인했습니다.

## ADR-032 수치 의미 — **확정 (D9)**
- `semantics`: `degree`(정성 표현 bands 필수) / `physical`(단위 필수, 숫자와 단위를 그대로 출력) / `ratio` / `position` / `count`(숫자 그대로 출력). 기본값은 `physical`입니다(Sprint 0의 동작과 호환).
- 원본 숫자는 항상 ImageSpec에 무손실 저장됩니다. 표현만 의미에 따라 달라집니다.
- 슬라이더는 unset일 때 흐린 상태로 보이고, 화면에 표시된 위치는 저장하지 않습니다. 사용자 입력 이벤트가 있을 때만 저장합니다.
- 모델이 수치를 정확히 구현한다고 주장하지 않습니다(UI 안내 문구 포함).

## ADR-033 정책 제한(restriction) — **확정 (D5)**
- 선택지의 `restriction { when, reason, policyRuleId }`이 성립하면 UI는 그 선택지를 **비활성으로 보이고 사유를 표시**합니다(숨기지 않음).
- 가져오기 등으로 이미 들어와 있으면 도메인 검증기가 `selection.restricted` 오류를 내고, 컴파일러가 출력 전체를 차단합니다(`policy.restricted_selection`). 미리보기, 복사, .txt 내보내기, 모바일 복사 모두 같은 관문을 거칩니다. 원본 명세는 보존합니다.
- Sprint 1 안전 정책(태그와 어휘 기반)은 그대로입니다. restriction은 UI 예방과 도메인 강제를 위한 추가 장치입니다.

## ADR-034 색상 컨트롤 — **확정 (D6)**

- **후속 개발 항목**: 사용자 정의 색상값은 새 값 타입(예: `{ kind: "color", hex }`, ImageSpec minor 버전 올림)과 색 이름 표현 정책이 필요합니다.

## ADR-036 화면 입력값과 저장값 분리 (범위·숫자 입력 결함 수정) — **확정**
- 범위: 최소·최대가 모두 유효할 때만 저장합니다. 한쪽만 입력하면 안내만 하고 저장하지 않으며, 표시용 기본값으로 나머지를 채우지 않습니다. 입력 취소, 오류 표시, 선택 해제, 새로고침 동작을 테스트했습니다.

- ID 영역: `person.expression.*`, `person.impression.*`, `person.makeup.*`, `person.clothing.*`(전체 설정) + `person.clothing.<의복>.*`(의복별), `person.accessories.*`. 같은 팔레트·어휘를 공유해도 값은 속성마다 독립적으로 저장됩니다.
- 반복 가능한 의복 객체는 도입하지 않았습니다(의복 종류는 카테고리별 단일 선택 + 사용자 정의). 후속 확장을 막지 않습니다.
- 적용 가능성은 기존 `noneOf`/`anyOf` + `whenUnset: "pass"` 조건으로 표현합니다: 메이크업 없음 → 다른 메이크업, 아이라인 없음 → 아이라인 색상, 의복 “없음” → 해당 의복의 세부, 의복 종류별 의미 없는 세부(민소매의 소매, 스커트의 바지 통 등), 플랫 굽 → 굽 형태, 안경 없음 → 안경테, 모자 없음 → 모자 색상. 값은 보존되고 다시 적용되면 출력됩니다.
- 의복 “없음”은 중립 문구(“no separate top garment”, “no outerwear”, “no visible innerwear”, “no footwear”, “no socks or hosiery”)로 출력하며 노출·나체 표현으로 바뀌지 않습니다. 커버리지·핏은 노출을 추가하지 않습니다.
- 실제 모순만 비차단 경고합니다: 미소 없음 + 다른 미소, 옅은/부드러운 + 활짝 웃는, 다문 + 벌린 미소, 입 다묾 + 치아 보임, 눈 감음 + 시선 상태, 불투명/비침 타이츠 + 반대 비침 정도, 액세서리 ‘없음’ + 다른 항목(7). 원피스 + 상의·하의, 레이어링은 진단하지 않습니다.
- 안전: 정책·어휘는 바꾸지 않았습니다. “앳된(youthful-looking)” 인상에는 기존 `age.ambiguous_young` 태그를 붙였고(기존 어휘의 “young-looking”과 같은 취급), 성숙한 인상은 연령 판단에 쓰이지 않습니다. 내의 선택지 중 기존 어휘에 걸리는 4개(“underwear”·“bra” 포함)는 미성년·모호 연령과 함께일 때만 기존 규칙으로 차단되며, 이를 피하려고 문구를 바꾸지 않았습니다(TD-12).

## ADR-068 Random Composer — **확정 (Sprint 2-D.6)**
- 카탈로그 전체를 대상으로 합니다. 승인되고 Basic 또는 Detailed에서 편집할 수 있는 모든 속성을 카탈로그 순서로 돌며, 적용 가능하고 값이 없는 속성에 등록된 선택지(활성·비제한) 또는 유효한 수치 범위의 값을 넣습니다. 새 속성도 자동으로 포함됩니다. 자유 입력과 사용자 정의 값은 만들지 않습니다. 피사체를 먼저 정하고(미설정이면 1인 인물), 나중에 적용되지 않게 된 값은 버립니다.
- **출처**: 랜덤 값은 기존 `preset` 출처에 예약된 origin `random_composer`를 쓰는 일반 선택값입니다. ImageSpec·저장 형식은 바뀌지 않습니다. 사용자가 고치면 기존 규칙대로 사용자 값이 됩니다.
- **보존**: 직접 설정(가져오기 포함)한 값, 추천 콘셉트 값, 프롬프트에서 제외한 값은 바꾸지 않습니다. 다시 생성하면 이전 랜덤 값만 새로 정하고, 적용되지 않게 된 이전 랜덤 값은 비웁니다. 마지막 실행은 기존 프리셋 되돌리기로 되돌립니다(제거된 값도 복원 — 세션 전용 거래 기록에 `after` 없는 변경 추가).
- **안전**: 구성 정책으로 성적 매력 표현(`sexy`), 미성년 연령대, 정확한 연령 수치, 실존·역사 인물, 속옷류, 상·하의 없음, 낮은 노출 범위를 생성하지 않습니다. 연령은 사용자가 연령 정보를 하나도 정하지 않았을 때만 성인 연령대로 정합니다. 그 다음 기존 안전 정책을 검사해 보류를 일으킨 랜덤 값만 빼며 최대 3회까지만 반복합니다. 사용자 값 때문에 생긴 차단은 그대로 둡니다.
- 예상 밖의 조합을 허용하며, 비차단 충돌 진단은 그대로 보여 줍니다. 원피스와 상·하의는 한쪽만 생성합니다. Sprint 3의 범용 속성 잠금은 만들지 않았습니다(“고정”은 직접 설정 또는 프롬프트 제외로 대신함).

## ADR-067 Recommended Mode와 Random Composer 로드맵 — **확정 (Sprint 2-D.5)**
- 추천 모드는 별도 데이터 구조 없이 **카탈로그 프리셋**(categoryId 없음 = 콘셉트)으로 구현합니다. 계획 → 확인 → 적용 → 되돌리기, 출처(`origin`), 사용자 수정 보호를 그대로 재사용합니다.
- 추천은 전체 방향(스타일·장소·분위기·구도·카메라·조명·화면비, 인물 콘셉트는 의상 스타일·자세·동작)만 제안합니다. 종족·성별·국적·연령·신체·얼굴·피부·헤어·외모·메이크업·표정은 설정하지 않습니다(단위 테스트로 고정). 피사체를 1인으로 정하는 것은 콘셉트 자체가 인물(캐릭터·초상·모델·선수)일 때뿐입니다.
- 새 적용 방식 `keepUser`: 비어 있는 속성과 **프리셋이 넣은 값**만 씁니다. 사용자가 직접 설정하거나 가져온 값은 바꾸지 않습니다. 추천 모드의 기본 동작이며, “직접 설정한 값도 바꾸기”를 눌러야만 덮어씁니다. 다른 콘셉트로 바꾸면 이전 콘셉트 값은 새 콘셉트 값으로 바뀝니다.
- 로드맵: 2-D.5 Recommended Mode, 2-D.6 Random Composer(요구사항 승인, 구현은 다음 지시서), 2-D.7 통합 및 사용성 개선(기존 2-D.6 항목과 TD-16 이동).

## ADR-065 안전 정책 0.3.0: 연령 미확인 성적 매력 표현 보류, 속옷류 의복 분류 — **확정 (Sprint 2-C.3, TD-12·TD-15)**
- 승인된 정책 변경(Sprint 2-C.3 지시서 §3·§5)입니다. 전체 내용과 비교표: [SAFETY_POLICY.md](SAFETY_POLICY.md).
- **TD-15: 연령 불명은 성인이 아닙니다.**
  - 성적 매력 표현은 구조화 연령 판단이 Adult일 때만 기존 허용 범위에 들어갑니다.
  - Minor·Ambiguous는 차단입니다(기존 `minor-sexualization`).
  - Unknown은 출력 보류입니다(새 규칙 `appeal-age-unconfirmed`, 차단과 같은 출력 제한).
  - 성인 확인은 컴파일러가 구조화 판단(`assessAge` = adult)에서만 만드는 `age.adult_confirmed` 신호입니다. 자유 입력의 “adult”·“25-year-old”는 성인 확인으로 인정하지 않습니다. 쉽게 꾸밀 수 있고 “명확한 성인 판단”이 아니기 때문입니다.
  - 일반적인 외모 표현(beautiful, handsome, pretty, cute, adorable …)은 신호가 아닙니다.
- **TD-12: 속옷류는 의복 분류입니다.**
  - underwear·bra·panties·속옷·팬티·브래지어를 성적 매력 어휘에서 빼서 새 신호 `garment.intimate`로 옮겼습니다.
  - 등록 선택지 8개(내복, 스포츠 브라, 일상용 브라, 보정 이너웨어, 브리프, 드로즈, 트렁크, 풀커버리지 하의)에도 같은 태그를 붙였습니다. 이제 같은 의미의 표현은 같은 결과를 냅니다. 0.2.0에서는 “underwear”는 신호였고 “briefs”는 아니었습니다.
  - 의복 종류나 소재로 노출을 추론하지 않습니다.
- **미성년자 보호는 완화하지 않았습니다(구현 판단).**
  - 0.2.0은 미성년·모호 연령 + “underwear/bra”를 (성적 표현으로) 차단했습니다.
  - 단어를 중립으로 바꾸면서 이 차단이 사라지지 않도록, 의복 분류 기반 규칙 `minor-intimate-apparel`로 옮겼습니다. 모든 속옷류에 같은 기준으로 적용합니다.
  - 결과적으로 미성년 + 브리프·트렁크·보정 이너웨어는 새로 차단됩니다(일관성 확보, 더 엄격).
  - 승인 범위 밖의 완화를 하지 않기 위한 판단입니다. 비교 매트릭스에서 차단 → 허용 변경은 0건입니다.
- “lingerie”·“란제리”는 단어가 성적 연출을 뜻하므로 성적 매력 표현으로 남겼습니다(동시에 속옷류 의복).
- 형식: 규칙에 `noneOf`(그 신호가 없을 때만)와 `resolution`(해결 위치 안내, `age`)을 추가했습니다. 같은 원인은 규칙 하나만 보고합니다.
- 버전: `prompter.baseline` 0.2.0 → 0.3.0, core 카탈로그 0.12.0(선택지 태그). ImageSpec과 컴파일러 버전은 그대로입니다. 컴파일러는 성인 확인 태그와 관련 설정 안내만 추가했고, 출력 형식은 같습니다.
- 한계: 키워드 기반이라 문맥 판단을 하지 못합니다. 정상적인 겹쳐 입기 같은 착용 맥락도 구분하지 못합니다. 사람이 아닌 피사체의 성적 매력 어휘도 연령이 설정될 때까지 보류됩니다(TD-17, Sprint 5).
- 비교 매트릭스: 1,010개 경우 가운데 변경 170개(보류 42, 신규 차단 52, 사유 변경 76), 불변 840개, 차단 → 허용 0개.
- Sprint 2-C.3 최종 승인: 미성년·모호 연령 속옷류 보호 규칙 유지를 포함해 승인되었습니다.

## ADR-066 외모 방향의 피사체 적용 조건 통일과 “설정으로 이동” — **확정 (Sprint 2-C.3, TD-14)**
- 외모 방향(`person.appearance.direction`)도 다른 인물 속성과 같은 공통 범위(`forPerson`)를 씁니다. 피사체가 1인 인물이거나 **미설정**이면 적용됩니다.
  - 명시적인 비인물 피사체와 “여러 사람”에는 적용하지 않습니다(값 보존, 복수 인물 확대 없음).
  - Detailed에서는 피사체를 고르지 않아도 인물 설정을 시작할 수 있습니다. 피사체를 자동으로 설정하지 않으며, 피사체 문장을 만들어 넣지도 않습니다.
- Basic은 같은 적용 조건을 쓰되, 안내형 흐름을 유지합니다. 피사체가 정해지지 않았고 값도 없으면 인물 전용 속성(외모 방향)을 아직 보여 주지 않습니다. 값이 있으면 항상 보여 주므로 값이 숨겨지지 않습니다. 표시 규칙일 뿐이며 출력·저장과는 무관합니다.
- 안내의 “관련 설정”은 버튼이며, 누르면 Detailed의 해당 속성으로 이동하고 포커스합니다.
  - Basic에서 누르면 Detailed로 전환됩니다. 모바일 미리보기 시트는 닫습니다.
  - 값을 바꾸지 않습니다(`GoToAttribute` 컨텍스트, Detailed 탐색 재사용).
- 적용 가능성과 안전 판단은 독립입니다. 적용되지 않는 값도 안전 검사를 받습니다.

## ADR-062 프롬프트 출력 순서: 카탈로그 `promptOrder` (UI 순서와 분리) — **확정 (Sprint 2-C.2, TD-08)**
- 문제: 속성 하나의 `order`가 UI 순서와 프롬프트 출력 순서를 함께 맡고 있었습니다(ADR-039). 새 영역을 끼워 넣으려면 번호를 다시 매겨야 했습니다(×10 공간, 비인물 +1000 오프셋 — ADR-051).
- 결정: 카탈로그 형식 0.5.0에 선택적 최상위 필드 `promptOrder`를 추가했습니다.
  - 순서가 있는 출력 그룹 목록이며, 각 그룹은 순서가 있는 속성 ID 목록입니다.
  - 컴파일러는 `registry.promptAttributes()`(생성 시 1회 평탄화)를 따릅니다. covers·의미 단위 대체·문장·안전 검사 순서가 모두 같은 순서를 씁니다.
  - UI는 지금처럼 `attributes()`(`order`)와 카테고리를 씁니다. 두 순서는 서로 영향을 주지 않습니다.
- 숫자 대신 목록을 쓴 이유:
  - 출력 그룹 안의 위치를 “어느 속성 다음”으로 명시해서, 새 속성은 ID 하나를 끼워 넣으면 됩니다. 다른 속성의 번호는 바뀌지 않습니다.
  - 동적 정렬이나 의존성 그래프 없이 결정적입니다.
- 무결성: 모든 속성이 정확히 한 번 나와야 합니다. 누락·중복·알 수 없는 ID·중복 그룹은 카탈로그 오류입니다. 새 속성은 출력 위치를 명시해야만 들어갈 수 있습니다.
- 호환:
  - `promptOrder`가 없는 카탈로그는 예전처럼 `order` 순서로 출력합니다.
  - core 0.11.0의 목록(`catalogs/prompt-order.ts`, 15개 그룹)은 0.10.0 출력 순서를 그대로 옮긴 것입니다.
  - 변경 전 코드로 기록한 골든 데이터와 비교했습니다: 카탈로그 3개 × 무작위 명세 120개 + 전체 속성 명세에서 프롬프트 해시와 문장 순서가 같습니다.
  - ImageSpec에는 순서 정보를 저장하지 않습니다(0.3.0 그대로).
- 버전: 카탈로그 형식 0.4.0 → 0.5.0(추가만), core 0.10.0 → 0.11.0(마이그레이션 `changes: []`), 컴파일러 0.4.0 → 0.5.0(같은 카탈로그 순서면 같은 출력).
- 테스트용 카탈로그는 추가 속성을 `placeUnlistedByOrder`(테스트 전용)로 예전 `order` 위치에 배치합니다.

## ADR-063 카테고리 초기화 이력 — **확정 (Sprint 2-C.2, TD-09)**
- 세션 안에서 최근 카테고리 초기화를 최대 5개까지 기록합니다(최신 순). 각 기록은 다음을 보존합니다:
  - 대상 카테고리, 순번(작업 순서), 시각
  - 지운 선택 객체 그대로: 값, 포함·제외, 사용자 정의 값, 프리셋 출처, 적용되지 않는 값
  - 그 뒤에 사용자가 바꾼 속성 목록(`editedSince`)
- 기록마다 따로 복원할 수 있습니다. 오래된 기록을 먼저 복원해도 됩니다.
- 복원 규칙:
  - 그 기록이 지운 속성 가운데 지금 미설정이고 초기화 뒤 바뀌지 않은 것만 되돌립니다.
  - 초기화 뒤 다시 설정했거나, 설정했다가 지운 속성은 현재 상태를 유지하고 알립니다.
  - 다른 카테고리의 변경은 그대로입니다. ImageSpec 전체를 과거로 되돌리지 않습니다.
- 사용자의 변경 판정은 리듀서 공통 처리 한곳에서 합니다. 동작 전후의 선택 객체 참조를 비교하므로 설정·해제·포함/제외·프리셋 적용과 되돌리기·다른 초기화와 복원이 모두 같은 방식으로 기록됩니다.
- 프리셋과의 관계:
  - 초기화는 기존처럼 프리셋 변경 내역에 “사용자 수정”으로 기록됩니다.
  - 초기화 뒤 적용한 프리셋 값은 복원보다 우선합니다.
  - 복원은 프리셋을 다시 적용하지 않습니다.
- 안전: 복원된 값도 컴파일 때 다른 저장값과 똑같이 안전 정책과 정책 제한 검사를 받습니다. 차단 대상이면 출력이 보류되므로 우회할 수 없습니다.
- 범위: 세션 메모리만 사용합니다(새로고침 후에는 없음). 전체 초기화·전체 초기화 되돌리기·JSON 가져오기·복구 적용은 명세 전체를 바꾸므로 이력을 비웁니다. 범용 Undo/Redo와 Sprint 3의 속성 잠금·프리셋 이력(TD-04)은 구현하지 않습니다.
- UI:
  - 최근 초기화 1개는 기존 막대의 “카테고리 초기화 되돌리기” 버튼으로 되돌립니다.
  - 이전 초기화는 접히는 목록에 카테고리·값 수·시각·“이후 n개 직접 수정”과 함께 표시하고, 항목마다 되돌리기 버튼을 둡니다.
  - 복원 결과(복원 수, 유지한 항목)는 안내로 보여 줍니다.

## ADR-064 속성 간 충돌 진단: 의미 충돌과 관례 차이 — **확정 (Sprint 2-C.2, TD-10)**
- 규칙에 선택 필드 `basis`를 두어 두 의미를 구분합니다:
  - `contradiction`: 의미가 서로 반대입니다. 경고(warning)이며 생략하면 이 값입니다.
  - `convention`: 일반적인 관례와 다르지만 정당한 표현입니다. 정보(info)입니다.
- 둘 다 비차단입니다. 값을 바꾸지 않고, 정리 버튼 같은 자동 조치도 두지 않으며, 출력도 그대로입니다. 안전 검사와는 독립적으로 동작합니다.
- 조건 `numberIn`(형식 0.5.0)을 추가했습니다. 수치 속성이 **설정되어 있고** 범위 안일 때만 참입니다. 미설정 슬라이더의 표시 위치는 값이 아니므로 추론하지 않습니다.
- 규칙 24개를 추가했습니다:
  - 의미 충돌 17개: 얼굴 2, 눈 2, 코 1, 입술 4, 신체 5, 표정 3
  - 관례 차이 7개: 조리개 ↔ 피사계 심도 2, 렌즈 ↔ 원근감 2, 빛 질감 ↔ 그림자 경계 2, 높은 대비 ↔ 그림자 없음 1
- 기존 규칙 `sky-light-in-studio`는 관례 차이로 분류만 바꿨습니다(심각도는 warning 그대로).
- 검토했지만 추가하지 않은 조합:
  - 렌즈 ↔ 초점 거리, 자세 ↔ 동작: 기존 규칙이 있음
  - 의복 종류 ↔ 세부: 적용 가능성이 이미 처리함
  - 눈썹 모양 ↔ 각도, 눈 모양 ↔ 크기: 서로 독립적인 축
  - 상·하체 길이 비율, 두 수치 사이 비교: 수치 대 수치 조건이 필요해 보류
  - 의미 근거가 약한 조합 전반
- 규칙은 기존과 같이 저장된 값을 기준으로 판단합니다. 프롬프트에서 제외했거나 현재 적용되지 않는 값도 진단합니다(기존 규칙과 같은 의미).
- 신체 규칙 5개는 신체 속성만 읽습니다(신원 참조 없음). ADR-052의 “신체 규칙 없음”을 이 범위에서 대체합니다(Sprint 2-C.2 최종 승인). 계속 유지하는 원칙:
  - 신체 속성 사이의 명확한 의미 충돌만 진단합니다.
  - 일반적인 신체 비율이나 외형을 강제하지 않습니다.
  - 성별·연령·국적에 따른 신체 특징을 추론하지 않습니다.
  - 의도적인 비현실적 표현을 제한하지 않습니다.
  - 진단은 비차단이며, 사용자 설정을 자동으로 고치거나 지우지 않습니다.
- UI:
  - 필드와 미리보기 안내에 “의미 충돌” 또는 “관례와 다름” 표시를 붙입니다.
  - 필드 안내에는 “관련 설정: <속성> (<페이지>)”를 함께 보여 줍니다.
  - 관례 안내는 정보 색으로 구분합니다.

## ADR-059 카테고리 탐색: WAI-ARIA 탐색 트리 — **확정 (Sprint 2-C.1, TD-01)**
- 검증 범위: jsdom(Testing Library)과 Playwright Chromium으로 역할·이름·설명·포커스·키 동작을 자동 검증했습니다.
- 실제 스크린 리더(VoiceOver·NVDA) 검증과 다크 모드 확인은 **미검증**입니다. Sprint 2-C.4 통합 검증 항목입니다(TD-16).
- ADR-058·060도 같은 범위입니다.
- 카테고리가 70개 이상이라 버튼마다 Tab을 멈추는 구조는 키보드 이동 비용이 큽니다. 그래서 APG의 탐색 트리 패턴을 택했습니다.
- 구조: `li[role=treeitem]` > 행 + `ul[role=group]`. 트리 전체의 Tab 정지점은 하나이고(roving tabindex), 그 위치는 현재 페이지(또는 보이는 가장 가까운 상위 항목)입니다.
- 키: ↑↓(이동), →(펼치기 / 첫 하위로), ←(접기 / 상위로), Home·End, Enter·Space(페이지 열기).
- 입력 문자로 이동(type-ahead)은 불필요한 사용자 정의 동작이라 넣지 않았습니다.
- 접근 가능한 이름은 `aria-labelledby`로 라벨만 씁니다.
  - `aria-owns`나 내용에서 이름을 계산하면 하위 항목까지 이름에 섞여 이를 피했습니다(테스트에서 발견).
  - 설정 수·경고·차단·설계 중·적용 불가 상태는 `aria-describedby`로 전달하고, 화면 배지는 장식으로 처리합니다.
- 상태: 현재 페이지는 `aria-current="page"`와 `aria-selected`, 펼침은 `aria-expanded`, 깊이는 `aria-level`로 전달합니다.
- 펼침 아이콘은 마우스 전용입니다(키보드는 ←/→).
- 데스크톱에서는 페이지를 열어도 포커스가 트리에 남습니다. 모바일 서랍에서 고르면 서랍이 닫히고 페이지 제목으로 포커스가 이동합니다.
- 검색 결과는 버튼 목록 그대로 두고, 결과 수를 `role="status"`로 안내합니다.

## ADR-060 모달과 비모달의 구분, 공통 `ModalDialog` — **확정 (Sprint 2-C.1, TD-02)**
- 프리셋 확인, 카테고리 초기화, 예시 확대는 공통 `ModalDialog`를 씁니다:
  - 초기 포커스는 `data-autofocus`(없으면 첫 포커스 대상)입니다. React `autoFocus`는 effect 전에 포커스를 옮겨 원래 위치를 잃게 하므로 쓰지 않습니다.
  - Tab과 Shift+Tab은 대화상자 안에서 순환하고, 배경은 `inert`가 됩니다(조상의 형제 요소). Escape로 닫힙니다.
  - 닫으면 연 요소로 포커스가 돌아갑니다. 그 요소가 사라졌거나 비활성화됐으면 `returnFocus()`를 씁니다. 예: 초기화 후에는 “카테고리 초기화 되돌리기”, 없으면 페이지 제목.
- 라이브러리는 없고, 네이티브 `<dialog>`는 jsdom에 `showModal`이 없어 테스트가 실제 경로를 검증하지 못하므로 쓰지 않았습니다.
- 색상 팔레트와 모바일 미리보기 시트는 **비모달**입니다. 포커스를 가두지 않고 배경도 inert로 만들지 않습니다. Escape로 닫으면 연 버튼으로 포커스가 돌아갑니다. 미리보기 시트는 열 때 제목으로 포커스를 옮깁니다.

- **외모 방향**(`person.appearance.direction`): Basic 단계 속성으로 `what` 그룹에서 피사체 바로 다음에, Detailed에서는 인상 및 매력 카테고리에 있는 **한 속성**이라 두 화면이 같은 값을 공유합니다. 적용 조건은 “피사체 = 인물”(미선택이면 미적용)로 두어 Basic에서 인물을 고른 뒤에만 보입니다. 정수 순서를 위해 피사체 순서를 200 → 190으로 옮기고 외모 방향을 195에 두었습니다(상대 순서·프롬프트 동일). 피사체 문구와 합치지 않고 독립 문장으로 출력합니다(컴파일러 변경 불필요). 의미가 같은 인상 값은 기존 `covers`로 한 번만 출력합니다.
- **자세**: `person_pose` 승인, 하위 분류 5개. 기존에 같은 의미의 속성이 없어 모두 신규(시선 상태·관찰 방향과는 별개 축). 신체의 “팔·손”·“다리·발”과 이름이 겹치지 않도록 하위 분류를 “팔·손 자세”·“다리·발 자세”로 했습니다. 제품 카탈로그에 DRAFT 영역이 없어져, 설계 중 화면(draft placeholder) 검증은 테스트 전용 카탈로그에서 `person_pose`를 DRAFT로 두고 계속합니다.
- **카메라**: 기존 Basic 속성 3개를 그대로 재사용하고 Detailed 속성 15개를 같은 카메라 화면에 추가(하위 분류를 만들면 기존 속성의 카테고리를 옮겨야 해 보류). 초점 거리·조리개는 실제 값을 문구로 가진 선택지 + 사용자 정의 값(수치형 속성은 정해진 단계 목록을 표현하지 못해 선택지로 구현). 모든 피사체에 적용.
- **조명**: Sprint 2-A 속성 6개는 ID·형식·기존 선택지를 유지하고 양 끝 단계 등 선택지만 추가(슬라이더로 바꾸면 값 형식이 바뀌어 저장 명세와 프리셋 의미 단위 대체가 깨짐). 새 속성 11개와 조명 색상 팔레트 14색. 림 라이트·그림자 “없음”의 적용 조건.

## ADR-055 TD-11 해결: 속성 테스트 비용 절감 — **확정 (TD-11 작업)**
- 원인 조사: CI의 push와 pull_request는 같은 작업(같은 실행기 이미지·Node·명령)입니다. 느린 실행에서는 이 테스트만이 아니라 Vitest 전체 시간이 같은 비율로 늘었습니다(빠른 실행 21–24초, 느린 실행 28–38초). 느린 실행은 push와 pull_request 모두에서 나타났습니다(2-B.5 마지막 측정에서는 push 3.11초 > pull_request 2.78초). 따라서 차이는 이벤트 종류가 아니라 **할당된 실행기의 성능 편차**이며, 테스트는 느린 실행기에서도 여유가 있어야 합니다. 로컬 병렬 실행 시간(2.7초)도 대부분 코어 경합 때문입니다(11코어 기기: 작업자 1개 0.76초, 4개 1.0초, 기본 10개 2.7초).
- 측정(단독 실행 1.09초 기준): 컴파일 2회 약 65%(검증·적용 가능성 약 30%, 안전 검사 약 25% — 주로 전체 프롬프트 검사), 명세 생성 14%, 조각별 `expect` 6만 회 8%, 깊은 비교 6%, 확장 레지스트리 생성 6%.
- 결과가 같은 최적화: `anyOf`/`noneOf` 조건을 배열 할당 없이 평가, 선택지별 적용 조건·정책 제한이 없는 속성은 선택지 검사를 건너뜀(동결된 속성별 캐시), 정책 제한 검사는 제한 가능한 속성만 순회, 값 검사를 컴파일당 1회 계산해 검증기와 공유, 안전 검사 항목별 정규식 전에 리터럴 포함 여부 확인, 문자 체계 감지에 ASCII 빠른 경로.
- 테스트 헬퍼: `buildSpec`은 여전히 모든 항목을 `applySelection`으로 적용하되 해당 속성의 이전 값에만 적용해 전체 맵을 매번 복사하지 않습니다. 기존 방식(`buildSpecByFold`)과 선택값·키 순서까지 같은지 새 테스트로 확인합니다.
- 속성 테스트: 조각마다 `expect`를 호출하던 출처 검사를 “선택값이 없는 조각 목록이 비어 있음” 단일 검사로 바꿨습니다(같은 조건, 실패 시 위반 조각을 모두 표시). 명세 수(500)·밀도(40%)·두 레지스트리·결정성 검사(2회 컴파일 + 깊은 비교)는 그대로입니다.
- 결과: 단독 실행 1.14초 → 0.81초. CI(같은 코드, 제한 5초): 빠른 실행기 1.79–1.91초(이전 2.62–3.11초), 느린 실행기 2.70–3.09초(이전 3.99–4.02초). 목표 2초는 빠른 실행기에서만, “안정적으로 3초 이내”는 느린 실행기에서 미충족 — TD-11은 부분 해결로 열어 둡니다. 더 줄이려면 전체 프롬프트 안전 검사 방식이나 표본 설계를 바꿔야 해서, 무리한 최적화를 반복하지 않고 멈췄습니다.

## ADR-054 컴파일 반복 계산 제거 — **확정 (Sprint 2-B.5 구현 판단)**
- 카탈로그가 커지며 500개 무작위 명세 속성 테스트(TD-11)가 느려져, 제한 시간을 늘리지 않고 컴파일 경로를 개선했습니다. 결과는 모두 동일합니다(기존 회귀·골든·동일성 테스트 전체 통과).
- `CatalogRegistry`: 선택지 ID 색인과 `lineage` 메모이제이션(카탈로그는 deep-freeze 되어 있어 무효화가 필요 없음; 등록되지 않은 ID는 캐시하지 않음).
- `compilePrompt`: 적용 가능성(`findInactiveSelections`)과 정책 제한(`findRestrictedSelections`)을 컴파일당 한 번만 계산해 검증기(`validateSpecAgainstCatalog`의 선택 인자)와 공유하고, 1차 패스의 활성 선택지를 2차 패스에서 재사용합니다.
- `evaluateSafety`: 텍스트별 검사 결과(신호별 일치 어휘)를 정책 객체별로 메모이즈합니다(512자 이하 텍스트, 최대 4096개 — 프롬프트 조각은 반복되고, 전체 프롬프트는 항상 새로 검사). 검사 순서·출처·중복 제거는 그대로이며 기존 동일성 테스트가 이를 확인합니다.
- 시험 후 채택하지 않은 것: 경계 조건을 앞으로 모은 합집합 정규식(이득 약 5%), 경계 없는 상위 집합 사전 필터(정밀 검사 증가), 리터럴 우선 형태(이득 약 16%) — 복잡도 대비 이득이 작아 넣지 않았습니다.
